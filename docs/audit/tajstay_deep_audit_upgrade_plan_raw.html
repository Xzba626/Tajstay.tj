SQLite в продакшне — база не масштабируется
Критично
Prisma настроена на SQLite (schema.prisma: provider = "sqlite"). При 1 000+ одновременных запросов базы данных SQLite блокирует запись, а файл dev.db лежит прямо в /prisma. Для 1 млн пользователей это сразу упадёт.
Решение: Мигрировать на PostgreSQL + Prisma Accelerate (connection pooling). Добавить PgBouncer или Neon serverless.
Файлы загружаются в /public/uploads — не для продакшна
Критично
Фото отелей и номеров сохраняются в public/uploads/hotel-covers/ и /room-photos/. При деплое через Docker/Vercel это папка пересоздаётся, все фото теряются. Хранение статики на диске не масштабируется.
Решение: Cloudflare R2 или AWS S3 + CloudFront CDN. Размер фото 343KB — нет оптимизации, нужен Sharp/WebP pipeline.
Аутентификация — .env содержит реальные секреты
Критично
Файл .env включён в ZIP-архив с паролями, JWT secret, API ключами. В .gitignore он есть, но в репозиторий попадал судя по git history. NEXTAUTH_SECRET хранится в незашифрованном виде.
Решение: Rotate все секреты немедленно. Использовать Vault/Doppler/Railway Secrets. Rate limiting на auth endpoints (сейчас нет).
Next.js 14.1.0 — устаревшая версия
Важно
Используется Next.js 14.1 вместо 15+. Нет Partial Prerendering (PPR), нет улучшенного кэширования. React 18.2 вместо 19. Отсутствует Server Actions в полной мере.
Решение: Upgrade до Next.js 15 + React 19. Включить PPR для search страниц.
Нет кэширования данных — каждый запрос в БД
Важно
searchApprovedHotels() вызывается на каждом рендере без unstable_cache или Redis. Страница /hotel/[id] делает полный JOIN при каждом запросе. При 10K RPS это будет стоить дорого.
Решение: Redis (Upstash) для кэша поиска + ISR для страниц отелей (revalidate: 60). Добавить React cache() для дедупликации.
Three.js на главной — тяжёлый бандл без lazy-loading
Важно
Hero3DScene.tsx и HeroThreeBackground.tsx подключают Three.js (~180KB gzip) в layout. Компонент рендерится только на десктопе, но бандл грузится всем. Нет dynamic import с ssr: false.
Решение: dynamic(() => import, { ssr: false, loading: () => <Placeholder/> }). Добавить IntersectionObserver для отложенной загрузки.
Нет rate limiting на API endpoints
Важно
Все API роуты (/api/bookings, /api/auth/email/login, /api/reviews) не имеют rate limiting. Возможны brute-force атаки на авторизацию и спам-бронирования.
Решение: Upstash Rate Limit middleware + Cloudflare WAF. Лимит: 5 попыток логина/минуту на IP.
Отсутствует OG/Meta теги — SEO не оптимизирован
Важно
generateMetadata() в layout.tsx возвращает только title и description. Нет og:image, og:locale (нужно для Таджикистана), structured data для отелей (Schema.org Hotel), hreflang для ru/tg/en.
Решение: Добавить динамические OG images через @vercel/og. Schema.org Hotel + Offer разметка для каждого отеля.
Нет error boundary и глобального error handling
Важно
При ошибке в компоненте вся страница падает. Нет error.tsx страниц кроме loading.tsx. Нет Sentry/аналога для отслеживания ошибок в продакшне.
Решение: Добавить error.tsx + global-error.tsx. Подключить Sentry с source maps.
Chat функционал — polling вместо WebSocket
Важно
BookingChatPanel.tsx судя по структуре использует REST polling. Для real-time чата это создаёт нагрузку. При 10K активных чатов — проблема.
Решение: Переключиться на Pusher Channels или Ably. Как минимум SSE (Server-Sent Events) вместо polling.
Internationalisation — только ru/tg/en, нет RTL
Улучшение
Система i18n через messages.ts хорошо структурирована, но нет поддержки Persian/Farsi (значимая аудитория в регионе) и RTL layout для арабского алфавита в таджикском.
Решение: Добавить fa (персидский) + RTL CSS с dir="rtl". Использовать next-intl вместо собственного решения.
Нет E2E тестов и unit тестов
Улучшение
Нет папки __tests__, нет jest.config, нет Playwright/Cypress. При рефакторинге для 1M пользователей без тестов — высокий риск регрессий.
Решение: Vitest для unit тестов сервисов. Playwright для critical paths: регистрация → поиск → бронирование → оплата.
Хорошая структура компонентов и TypeScript
Хорошо
Чёткое разделение на /components, /widgets, /processes, /lib, /shared. Zod валидация на API. Prisma типы автоматически. Это хорошая основа для масштабирования.
Хорошая UX архитектура — AI рекомендации, 3D эффекты
Хорошо
AIRecommendationLab, HeroThreeBackground, ViewTransitionLink, GSAP анимации — это уже выше среднего. Snap-scroll секции создают premium ощущение. Хорошая стартовая точка для визуального апгрейда.
